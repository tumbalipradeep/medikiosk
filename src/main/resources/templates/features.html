Features

Implemented today — and where to see the proof

Every item below is backed by running application behavior. Nothing here is a decorative showcase; each feature has a place in the product where you can click through to the real data, state, and security.

Patient intake conversation

A guided, language-aware conversation (English, Hindi, Telugu, Tamil, Kannada) that collects the health concern, flags it with deterministic rules, and lets the patient review before finishing. When no AI provider is configured, intake continues with a deterministic question planner as a fallback.

See it: sign in with the patient demo account →

Document scan with provenance

Reports are validated by content (magic bytes), stored securely, and processed by PDF text extraction (pdfbox). The extraction method, provider, and source language are recorded and surfaced in the physician workspace. Image OCR and handwriting recognition honestly report NOT_IMPLEMENTED.

See it: live capability report (OCR) →

Conservative clinical findings

Vitals, labs, and medications are parsed deterministically. A lab value without a printed reference range is marked UNKNOWN — it is never upgraded to normal or abnormal. System flags always require clinical review.

See it: physician workspace findings →

Physician review workspace

Case assignment, an itemized answer review with decision records, a clinical timeline built from persisted events, and a finalized consultation. The workspace distinguishes the patient's own words, extracted data, and physician-reviewed information.

See it: sign in with the physician demo account →

Security & authorization

Role-based access is enforced by the backend for patient, physician, and admin routes. Cross-patient uploads and listings are rejected. Login policy covers lockout, activation state, and forced password change.

See it: admin account console →

Audit trail & integration boundaries

Significant actions create a persisted audit event. FHIR exports and HIS/ABDM transmission are explicitly local-only in this deployment — the admin console shows their honest status rather than pretending they are live.

See it: how data is handled →

Capability honesty. The application never relabels an unavailable capability as working. OCR, handwriting recognition, and external transmission remain honest NOT_IMPLEMENTED / local-only until a real, credential-verified engine is integrated.
