# M5.3 — Final Hardening & Kill Test (evidence record)

The final milestone is an adversarial kill test of the whole MediKiosk journey,
upheld against a fixed set of honest-demo hygiene rules. Every claim below was
exercised against a live instance on port 8081 and against the offline Maven
test suite. No PII, live case identifiers, or patient data appear in this
record or in the repository.

## Honesty rules enforced throughout M5.3
1. No fabricated ABHA / Aadhaar / ABDM identifiers or transmissions; the kiosk
   declares a `LOCAL` identity and stores everything locally.
2. No autonomous diagnosis, prescription, or safety assessment anywhere; the
   red-flag layer is deterministic keyword triage labelled "not a diagnosis".
3. No fake AI: without environment-provided credentials no provider is
   enabled, and the deterministic canonical wording is used instead.
4. No clinical payloads in URLs, browser storage, console logs, or audit rows;
   audit rows carry identifiers and outcome only.
5. FHIR export is a local projection only, with real HL7/UCUM/UUID code
   systems and no fabricated LOINC/SNOMED.

## How to reproduce
- Unit/integration: `mvn -o -q clean test` (offline; PostgreSQL via test
  profile).
- Live demo: start PostgreSQL, `mvn -o spring-boot:run`, then walk the
  patient → physician journey below in a browser.

## Resolved defects found by the kill test
- Mid-conversation start previously wiped the in-progress result (data loss);
  it now resumes, and only the explicit RESTART clears. Regression test
  re-captured the new contract.
- A template rendered the red-flags card only when flags exist, so a
  zero-flag case could be misread as "not checked"; the card now always
  renders with a `None detected` badge and "no red flags were identified"
  text.
- A canned patient bubble and fabricated ABDM messaging were removed from the
  intake/completion templates.
- Demo retrofit left a query-string caseId on the completion URI; the
  completion page now derives the case strictly from the session.
