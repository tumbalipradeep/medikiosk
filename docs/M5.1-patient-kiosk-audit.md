# M5.1 Patient Kiosk Experience — Internal Audit

Internal engineering audit for the MediKiosk patient journey (SIH26047). This
document records the state of the patient-facing flow *before* the M5.1 change
set is applied, the gaps found against the M5.1 requirements, and the intended
fixes. It is an engineering working document, not a user-facing artifact.

Date: 2026-09-11 (M5.1 checkpoint). Baseline: 579 tests / 71 classes / 0
failures / 0 errors / 0 skipped (`mvn -o -q clean test`, exit 0).

## 1. Current journey (mapped from code)

Current patient pages are served by server-rendered Thymeleaf templates with a
Vanilla-JS conversation client:

- `/patient/home` — `patient/home.html` + `PatientHomeController`
  Landing page for an authenticated patient (redirect target for patient login
  via `RoleBasedSuccessHandler`). Contains a stale alert: "Clinical case-taking
  will be added in a later checkpoint." The case-taking feature has existed
  since M3/early M4, so this text is factually wrong.
- `/patient/identify` — **does not exist**. There is no identity abstraction,
  no explicit patient-identity step, and no ABHA-ready boundary. The app simply
  assumes the logged-in local user.
- `/patient/consent` — `patient/consent.html` + `PatientConsentController`
  Granular consent toggles (Clinical Case-Taking, Audio Capture, Document
  Processing, Data Sharing) plus the "Start Clinical Case-Taking Session"
  action. Language cannot be selected here.
- `/patient/intake` — `patient/intake.html` + `PatientSessionController.intake`
  Session-scoped language selector (English/Hindi/Telugu/Tamil/Kannada), the
  chat conversation, voice ASR/TTS, and document upload surfaced only after the
  conversation completes.
- `/patient/intake/conversation/start`, `/patient/intake/conversation/answer`
  — `ClinicalIntakeConversationController`
  Stateless, deterministic 25-question conversation (7 SOCRATES/HPI + 10
  Dashavidha + 8 Ahara-Vihara). At the final Ahara-Vihara answer the case is
  registered in the review store and persisted
  (`CompletedCasePersistenceService`).
- `/patient/intake/language`, `/patient/intake/voice/asr|tts` — language and
  voice services.

## 3. Intended fixes (design)

1. **Identity boundary** — add `PatientIdentityProvider` (interface) with a
   single `LocalPatientIdentityProvider` implementation that resolves the
   logged-in local patient to a `PatientIdentity` in `LOCAL/DEMO` mode, with an
   explicit "not linked to ABHA/ABDM" marker and *no* invented ABHA/Aadhaar
   number. Add `/patient/identify` (welcome step) that renders this resolution
   and lets the patient proceed to consent. Future real-ABHA provider would slot
   in behind the same interface.
2. **Genuine multilingual questions** — add `QuestionLocalizationService`
   providing curated offline translations of all 25 canonical question texts in
   Hindi, Telugu, Tamil, Kannada (English stays canonical DETERMINISTIC).
   `ClinicalIntakeConversationController` resolves the session language and
   serves translated question text; the shown wording is recorded faithfully via
   a new `QuestionSource.TRANSLATED`, with `answer_language` capturing the
   BCP-47 tag actually used.
3. **Language name + persistence** — add `nativeName` to `SupportedLanguage`
   and to the language selection payload; keep the existing `code/label/bcp47`
   fields (tests depend on them). Let consent/home surfaces expose the same
   selector so the choice persists across pages before the intake begins.
4. **Honest progress** — add `answeredCount`/`totalCount` to
   `ClinicalIntakeResponse` (derived from real session state, never fabricated)
   and render a section stepper (History → AYUSH Assessment → Lifestyle →
   Review) driven by these counts.
5. **Session lifecycle** — add `PatientSessionService.complete(userId)` and
   `PatientSession.markCompleted()`; mark the session COMPLETED when the case is
   persisted so a genuinely finished patient can start a fresh session.
6. **Duplicate protection** — completion is idempotent: once a case has been
   persisted for this HTTP session, re-answering the final step returns the
   original `caseId` and re-saves nothing; a multi-host session marker
   (`completedCaseId`) is exposed to the intake template so a refresh on the
   finished screen shows a completion summary instead of silently restarting
   the conversation; `beforeunload` warns mid-conversation.
7. **Review + complete** — after completion the patient gets a review summary
   (plain-language, patient-safe) with a deliberate "Submit & Finish" action and
   a dedicated completion page with honest local/demo wording.
8. **Red flags** — soften the headline to "Flagged for clinical review", add
   plain-language reassurance, keep the server-side URGENT semantics, and alert
   readers via `role="alert"`/`aria-live`.
9. **Documents** — bigger touch-friendly upload target, plain-language guidance
   (prescriptions / lab reports / discharge summaries), and patient-safe error
   text.
10. **Accessibility** — larger touch targets, `role="status"` region for
    mic/listen/progress announcements, labelled controls, focus management,
    visible contrast, no color-only signalling.
11. **Completeness** — new integration/security tests covering identity,
    progress, localization, idempotent completion, review, and the session
    lifecycle; browser E2E (English + Telugu + one more language; normal and
    failure flows); SIH26047 review matrix.

## 4. Resolution status (applied with M5.1)

All gaps G1-G13 were addressed in the M5.1 change set. Evidence:

- **Identity**: `PatientIdentity`/`LocalPatientIdentityProvider` +
  `PatientIdentifyController` (`/patient/identify`, `/patient/identify/confirm`);
  `PatientIdentityProvider` is the ABHA-ready boundary; demo mode stays LOCAL.
- **Localization**: `QuestionLocalizationService` (curated offline translations of
  all 25 questions in hi/te/ta/kn), `QuestionSource.TRANSLATED`, per-question
  language + source recorded in the clinical record.
- **Progress**: `answeredCount`/`totalCount` in every step response; stepper +
  `aria-current` in `intake.html`; preserved when switching language mid-
  conversation (`intake.js` keeps last-known progress state).
- **Red-flag honesty**: `redFlagTitle` wording replaced "urgent/critical" language;
  banners use `role="alert"`, seek-urgent-care note on review and complete pages.
- **Documents**: upload/list/delete surfaced in the review step; ownership enforced.
- **Session lifecycle**: `PatientSession.markCompleted` + `PatientSessionService.complete`;
  `PatientSessionController.clearStagingHttpSession` on a new `/patient/session/start`; repeat
  visits work; `completedCaseId` handed to the intake template via `meta[name=completed-case]`.
- **Idempotent completion**: final answer persists the case exactly once per HTTP
  session (`COMPLETED_CASE_ATTRIBUTE`); duplicates return the same `caseId`;
  `/restart` is the explicit genuinely-new-case boundary.
- **Review**: `GET /patient/cases/{caseId}/summary` (ownership-checked) fills the
  in-conversation review panel; `GET /patient/intake/complete?caseId=` shows the
  honest completion page; `complete.html` states demo mode, no ABHA/ABDM.
- **Home**: `/patient/home` rewritten with identity card, 5-step journey preview,
  and latest-case info; stale "later checkpoint" alert removed.
- **Accessibility**: `aria-live` status region, labelled controls, large touch
  targets (`btn-lg`/`btn-lg-mobile`), `role=log` chat.
- **Completeness**: `M5PatientKioskJourneyTests` (18 new tests), full regression
  597 tests / 0 failures / 0 errors / 0 skipped, browser-equivalent E2E
  (English + Telugu + Kannada; normal + failure flows) PASS, `docs/SIH26047-matrix.md`.

Known honest limitation (recorded, not hidden): red-flag detection matches
English keywords; the matrix documents this explicitly.

## 5. Constraints respected

- No Aadhaar, no fake ABHA number, no ABHA/ABDM connectivity claims.
- No weakening of `SecurityConfig` (`/patient/**` stays PATIENT-only).
- Clinical record remains server-side source of truth; nothing sensitive is
  stored in `localStorage`/`sessionStorage`/URL parameters/console.
- Deterministic offline behaviour preserved (no network, no AI dependency for
  correctness of the record).
- Existing test-pinned contract preserved: `chatWindow`/`chatMessages`/
  `assistantGreeting`/`messageInput`/`sendButton`/`micButton`/`speakQuestion`/
  `currentLangBadge`/`languageSelect` ids, patient-login redirect to
  `/patient/home`, "Consent & Privacy Choices" and "Clinical Case-Taking" consent
  strings, `$.code/$ .label/$.bcp47` language payload, `$.caseId` non-blank at
  completion, and question jsonPath fields.
